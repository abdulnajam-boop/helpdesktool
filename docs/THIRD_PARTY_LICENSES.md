# Third-party licenses

Date: 2026-08-20. Companion to `docs/DEPENDENCY_AUDIT.md` (full version/
CVE detail) — this document exists specifically to answer "what license
obligations does each third-party dependency actually carry," in one
place, without needing to cross-reference PyPI/npm pages.

**This is not a legal opinion.** It records the license each dependency
actually declares (via `importlib.metadata`'s `License-Expression` field
for Python packages, and each package's own `package.json` `license`
field for npm packages — read directly from the installed packages, not
assumed from memory) and states plainly what that license conventionally
requires. Whether that's sufficient for any particular deployment,
jurisdiction, or business context is a question for qualified legal
review, not this document.

## This project's own license

`pyproject.toml` declares `license = { text = "Apache-2.0" }`.

**Finding: no `LICENSE` file exists at the repository root.** A license
declared in package metadata without a corresponding `LICENSE` file
committed to the repository is an inconsistency worth fixing —
deliberately not auto-generated by this pass, since the correct license
text needs a real copyright holder name and year, which is the repository
owner's decision, not something to invent. Flagged here as an action
item; see `docs/HELPDESK_MATURITY_GAP_ANALYSIS.md`.

## Backend — the one non-permissive license

| Package | License | What it actually requires |
|---|---|---|
| **psycopg** (`psycopg[binary]`) | **LGPL-3.0-only** | The GNU Lesser General Public License permits linking an LGPL library into a proprietary/closed-source application without that application itself becoming LGPL — the copyleft obligation is scoped to the library's *own* source: if `psycopg`'s source were modified and redistributed, those modifications would need to be made available under LGPL-3.0. This project uses `psycopg` unmodified, as installed from PyPI, which is the conventional, unencumbered case. Recorded explicitly rather than silently treated the same as the MIT/BSD packages above, since it is not the same category of license. |

## Container base images

`python:3.13-slim`, `node:22-alpine`, `nginx:1.31-alpine`,
`postgres:17` — each is itself built from many upstream packages (glibc/
musl, OpenSSL, etc.) under a mix of permissive and copyleft licenses
(e.g. glibc is LGPL). This project consumes these images unmodified as
published by their respective maintainers (Python Software Foundation,
OpenJS Foundation/Node.js, F5/NGINX, PostgreSQL Global Development
Group) — auditing every transitive OS-package license inside each base
image is out of scope for this document; `trivy`'s scan (CI's `docker`
job) covers *vulnerabilities* in those images, not license obligations.

## What this project has never done, stated for the record

No code in this repository is copy-pasted or vendored from another
project's source under a license this document doesn't account for —
every third-party capability used here is consumed as an installed
package via `pip`/`npm` from its official registry (PyPI/npm), declared
in `pyproject.toml`/`frontend/package.json`, never fetched or embedded ad
hoc at build or runtime. See `docs/SOFTWARE_PROVENANCE.md` for the fuller
provenance statement, including the explicit confirmation that nothing in
this codebase fetches and executes remote code at runtime.
